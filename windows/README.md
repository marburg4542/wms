# สคริปต์สำหรับเครื่องที่รันระบบจริง (Windows)

ไฟล์ในโฟลเดอร์นี้มีไว้ใช้บน **เครื่องที่รัน WMS ให้ทั้งบริษัทใช้** ไม่ใช่เครื่องที่ใช้พัฒนา

ทุกไฟล์หาโฟลเดอร์โปรเจกต์จากที่อยู่ของตัวเอง จึงย้ายโปรเจกต์ไปไดรฟ์ไหนก็ได้โดยไม่ต้องแก้อะไรข้างใน

> **ทำไมข้อความข้างในเป็นภาษาอังกฤษ** — cmd.exe อ่านไฟล์ `.bat` ทีละไบต์ พอมีอักษรไทย
> ตำแหน่งไบต์จะเลื่อน แล้วแปลคำสั่งผิดจนสคริปต์พัง โดยเฉพาะส่วนที่มีวงเล็บกับ `goto`
> (ทดสอบแล้วพังจริง) ไฟล์พวกนี้จึงเป็นอังกฤษล้วนโดยตั้งใจ ส่วนคำอธิบายภาษาไทยอยู่ในไฟล์นี้แทน

---

## เครื่องเซิร์ฟเวอร์มีสองส่วน สคริปต์ชุดนี้ดูแลแค่ส่วนเดียว

อ่านข้อนี้ก่อน ไม่งั้นจะเข้าใจผิดว่าระบบเปิดเองได้ไม่ครบ

| ส่วนที่ต้องมีชีวิต | ใครเปิดให้ | ตั้งค่าที่ไหน |
|---|---|---|
| ตัวเซิร์ฟเวอร์ WMS (พอร์ต 5000) | `run-wms.bat` ผ่านงานของ Windows | `install-wms-task.bat` ในโฟลเดอร์นี้ |
| ท่อ Cloudflare (ทำให้เข้าจากข้างนอกได้) | **Windows เปิดเองในฐานะบริการ** | `cloudflared.exe service install <token>` ทำครั้งเดียวตอนติดตั้งเครื่อง |

สคริปต์ในโฟลเดอร์นี้ **จงใจไม่ยุ่งกับท่อเลย** เพราะ Windows ดูแลให้ดีกว่า — คอยเปิดใหม่ให้ถ้าท่อตาย มีบันทึกของตัวเอง และเริ่มทำงานตั้งแต่ก่อนใครล็อกอิน

ถ้าเอาท่อมาผูกไว้ในสคริปต์เดียวกับเซิร์ฟเวอร์ จะกลายเป็นว่าท่อต้องรอให้เซิร์ฟเวอร์ตายก่อนถึงจะได้เปิดใหม่ ทั้งที่สองอย่างนี้ไม่เกี่ยวกันเลย

---

## ใช้ไฟล์ไหนตอนไหน

| ไฟล์ | ใช้เมื่อไหร่ | ต้อง Run as administrator |
|---|---|---|
| `install-wms-task.bat` | **ครั้งเดียว** ตอนตั้งเครื่องใหม่ | ใช่ |
| `update-wms.bat` | ทุกครั้งที่มีการแก้โค้ดแล้ว push ขึ้น GitHub | ใช่ |
| `stop-wms.bat` | ตอนจะหยุดระบบชั่วคราว | ใช่ |
| `start-wms.bat` | ตอนจะเปิดกลับหลังกดหยุด | ใช่ |
| `run-wms.bat` | **ไม่ต้องแตะ** — Windows เรียกเองตอนเปิดเครื่อง | — |

ทุกไฟล์ต้อง **คลิกขวา → Run as administrator** ถ้าดับเบิลคลิกเฉยๆ มันจะเตือนแล้วปิดไปเอง ไม่ทำอะไรครึ่งๆ กลางๆ

---

## ตั้งครั้งแรก

รัน `install-wms-task.bat` หนึ่งครั้ง มันจะบอก Windows ว่า "ทุกครั้งที่เปิดเครื่อง ให้เปิด WMS ด้วย"

งานนี้ถูกตั้งในนามบัญชี **SYSTEM** ของ Windows ไม่ใช่บัญชีของคนใดคนหนึ่ง — แปลว่าระบบจะกลับมาเองตั้งแต่ตอนบูต **โดยไม่ต้องรอให้ใครมาล็อกอิน** ถ้าไปผูกกับบัญชีคน เครื่องที่รีสตาร์ตกลางดึกเพราะ Windows Update จะยังเข้าไม่ได้จนกว่าจะมีคนมาเปิดเครื่องตอนเช้า

ตัวติดตั้งจะเช็คให้ก่อนว่ามี `server\.env` แล้วหรือยัง ถ้ายังไม่มีมันจะไม่ยอมตั้งงานให้ เพราะเซิร์ฟเวอร์จะสตาร์ตไม่ขึ้นอยู่ดี

**การทดสอบเดียวที่เชื่อถือได้:** สั่ง restart เครื่องหนึ่งครั้ง แล้วรอโดย**ยังไม่ล็อกอิน** ถ้าเปิดเว็บจากมือถือได้ทั้งที่หน้าเครื่องยังเป็นหน้าจอล็อกอินอยู่ = ผ่านจริง ทั้งเซิร์ฟเวอร์และท่อ

---

## เวลาแก้โค้ด

1. แก้และทดสอบที่**เครื่องพัฒนา** แล้ว push ขึ้น GitHub
2. มาที่เครื่องนี้ รัน `update-wms.bat`

มันจะหยุดระบบ → ดึงโค้ดใหม่ → ติดตั้งส่วนประกอบ**เฉพาะเมื่อจำเป็น** → สร้างหน้าเว็บใหม่ → เปิดระบบกลับ แล้วเช็คให้ด้วยว่ากลับมาจริงไหม

**เรื่องความเร็ว** — ขั้นติดตั้งส่วนประกอบจะทำก็ต่อเมื่อรายการ package เปลี่ยนจริงเท่านั้น (เทียบจาก `package-lock.json`) การแก้โค้ดทั่วไปไม่ไปแตะไฟล์นั้น รอบอัปเดตปกติจึงใช้เวลาแค่หลักสิบวินาที ส่วนรอบที่มี package ใหม่จะนานหลายนาทีและ**ดูเหมือนค้าง** — อย่าปิดหน้าต่าง หน้าจอจะบอกเองว่ากำลังทำอันไหนอยู่

หลังอัปเดตเสร็จ บอกพนักงานให้กด `Ctrl+Shift+R` หนึ่งครั้ง เพราะเบราว์เซอร์เก็บหน้าเว็บเวอร์ชันเก่าไว้

---

## กฎที่ห้ามพัง

**เครื่องนี้เป็นสำเนาของ GitHub เท่านั้น ห้ามแก้ไฟล์ใดๆ บนเครื่องนี้**

ถ้ามีใครแก้ไฟล์ไว้ `update-wms.bat` จะหยุดแล้วเตือน ไม่เดินต่อ — จงใจให้เป็นแบบนั้น เพราะถ้าปล่อยผ่าน การดึงโค้ดจะชนกันเงียบๆ แล้วหน้าจอจะบอกว่าอัปเดตเสร็จ ทั้งที่ระบบยังรันโค้ดเก่าอยู่ อาการนี้หาสาเหตุยากมาก

**ข้อมูลไหลทางเดียว** — โค้ดไหลเข้ามาจาก GitHub ส่วนข้อมูลจริงไหลออกไปเป็นไฟล์สำรองเท่านั้น **ห้ามเอาไฟล์ฐานข้อมูลจากเครื่องพัฒนามาทับเครื่องนี้เด็ดขาด** ไม่ว่าด้วยเหตุผลอะไร เพราะงานที่พนักงานทำไปจะหายทั้งหมดในพริบตา

---

## ถ้าเปลี่ยนพอร์ต

สคริปต์ที่ต้องเช็คหรือหยุดเซิร์ฟเวอร์มีบรรทัด `set "APP_PORT=5000"` อยู่ด้านบน **ต้องตรงกับ `PORT` ใน `server\.env`** ถ้าเปลี่ยนพอร์ตต้องแก้ทั้งสองที่ ไม่งั้นสคริปต์จะหยุดเซิร์ฟเวอร์ไม่ได้และรายงานผลผิด

ที่ต้องอ้างพอร์ตเพราะสคริปต์เล็งหยุด**เฉพาะตัวที่ฟังอยู่ที่พอร์ตนั้น** ไม่ใช่ปิด node ทุกตัวบนเครื่อง — เครื่องพัฒนามี node รันอยู่พร้อมกันได้สิบกว่าตัว รวมถึงเครื่องมือที่กำลังใช้งานอยู่

---

## เวลาระบบมีปัญหา

เปิดไฟล์ `wms.log` ที่โฟลเดอร์บนสุดของโปรเจกต์ — ทุกอย่างที่เซิร์ฟเวอร์พิมพ์ออกมาถูกบันทึกไว้ที่นั่นพร้อมวันเวลา

| อาการ | น่าจะเป็นเพราะ |
|---|---|
| `wms.log` มีบรรทัด `WMS stopped … restarting in 15s` ซ้ำถี่ๆ | เซิร์ฟเวอร์เปิดแล้วตายวนอยู่ ดูข้อความเหนือบรรทัดนั้น ที่เจอบ่อยคือ `server/.env` หายหรือตั้งค่าผิด |
| เปิดเว็บจากข้างนอกขึ้น error 530 แต่ `http://localhost:5000` ในเครื่องใช้ได้ | **ท่อไม่ได้ต่อ ไม่ใช่ปัญหาของสคริปต์ชุดนี้** ไปดูบริการ cloudflared |
| เปิดเว็บได้แต่หน้าเป็นเวอร์ชันเก่า | เบราว์เซอร์ยัง cache อยู่ กด `Ctrl+Shift+R` |
| เข้าระบบได้แต่ไม่มีสินค้าเลยสักรายการ | ระบบไปเปิดฐานข้อมูลเปล่า ตรวจ `DB_FILE` ใน `server\.env` ว่าตรงกับชื่อไฟล์จริง |
