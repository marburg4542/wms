สำหรับกรณีย้ายระบบที่ใช้งานอยู่แล้วไปเครื่องใหม่ หรือเปลี่ยนโดเมน
(ถ้าเป็นการ**ติดตั้งใหม่ตั้งแต่ต้น** ให้ใช้ [CLOUDFLARE_SETUP.md](CLOUDFLARE_SETUP.md) แทน)

ตัวแทนค่าในเอกสารนี้:

| ตัวแทน | ตัวอย่าง |
|---|---|
| `<เครื่องเดิม>` | `C:\Users\Lenovo\Documents\Personal_Projects\WMS_ICS` |
| `<เครื่องใหม่>` | `D:\apps\wms` |
| `<โฮสต์ใหม่>` | `wms.company.com` |

## สรุปสั้น: ต้องย้ายอะไรบ้าง

| # | ย้ายอะไร | ขนาดโดยประมาณ | ถ้าลืมจะเป็นยังไง |
|---|---|---|---|
| 1 | ฐานข้อมูล `identifier.sqlite` | ~1 MB | ข้อมูลทั้งระบบหาย |
| 2 | โฟลเดอร์ `server/uploads/` | ~160 MB | รูปสินค้าหายหมด (ข้อมูลอื่นยังอยู่) |
| 3 | ไฟล์ `server/.env` | เล็กมาก | **เซิร์ฟเวอร์สตาร์ทไม่ขึ้นเลย** |
| 4 | โค้ดโปรเจกต์ | ~30 MB | — |

**ไม่ต้องย้าย** (สร้างใหม่บนเครื่องปลายทาง): `node_modules/`, `dist/`, `server/backups/`

## ⚠️ ขั้นที่ 0 — ตรวจโดเมนก่อน

ถ้าเปลี่ยนไปใช้โดเมนใหม่ ต้องเช็คว่าโดเมนนั้นอยู่บน Cloudflare แล้วหรือยัง:

```powershell
nslookup -type=NS <โดเมนใหม่>
```

ต้องขึ้นชื่อลงท้าย `ns.cloudflare.com` ถ้าไม่ใช่ **ต้องให้ฝ่าย IT ย้าย nameserver มา Cloudflare ก่อน**
และต้องคัดลอก DNS record เดิมมาให้ครบก่อนย้าย ไม่งั้น**อีเมลองค์กรจะล่ม** (รายละเอียดใน CLOUDFLARE_SETUP.md ขั้นที่ 0)

## ขั้นที่ 1 — สำรองข้อมูลจากเครื่องเดิม

> ⛔ **ห้ามคัดลอกไฟล์ `identifier.sqlite` ตรงๆ ขณะระบบยังรันอยู่**
> ฐานข้อมูลใช้โหมด WAL — ข้อมูลล่าสุดบางส่วนอยู่ในไฟล์ `-wal` แยกต่างหาก
> ถ้าคัดลอกแค่ไฟล์หลักจะได้ข้อมูลเก่ากว่าความจริงโดยไม่มีอะไรเตือน

**บนเครื่องเดิม:**
```powershell
cd <เครื่องเดิม>\server
npm run backup
```

จะได้โฟลเดอร์ `server\backups\<วันเวลา>\` ที่มี:
- `identifier.sqlite` — ฐานข้อมูลฉบับสมบูรณ์ (ปลอดภัย ใช้ `db.backup()` ของ SQLite)
- `uploads\` — รูปภาพทั้งหมด

**คัดลอกไฟล์ `.env` แยกต่างหากด้วย** เพราะ `npm run backup` **ไม่ได้สำรองไฟล์นี้**:
```powershell
copy <เครื่องเดิม>\server\.env  <ที่เก็บชั่วคราว>\env-backup.txt
```

## ขั้นที่ 2 — เตรียมเครื่องใหม่

1. ติดตั้ง **Node.js 22 LTS** (ต้องเป็น major เดียวกับเครื่องเดิม)
1. ตรวจว่ามี **Google Chrome หรือ Microsoft Edge** บนเครื่อง — ระบบใช้เบราว์เซอร์ตัวนี้
   สร้างไฟล์ PDF ของรายงาน (Windows มี Edge ติดมาอยู่แล้ว จึงมักไม่ต้องทำอะไร)
   ถ้าติดตั้งไว้ที่อื่นนอกตำแหน่งมาตรฐาน ให้ตั้ง `PDF_BROWSER` ใน `server/.env`
   ชี้ไปที่ไฟล์โปรแกรมโดยตรง เช่น
   `PDF_BROWSER=D:\Apps\Chrome\chrome.exe`
2. สร้างโฟลเดอร์ `<เครื่องใหม่>` — **อย่าวางใน `C:\Users\<ชื่อคน>\`**
3. คัดลอกโค้ดทั้งโปรเจกต์มา **ยกเว้น** `node_modules/`, `dist/`, `server/backups/`
4. ติดตั้ง dependency ใหม่:
   ```powershell
   cd <เครื่องใหม่>
   npm ci
   cd server
   npm ci
   ```

> ⚠️ **ห้ามคัดลอก `node_modules` ข้ามเครื่อง** — `better-sqlite3` เป็น native module
> ที่คอมไพล์ผูกกับเครื่องและเวอร์ชัน Node ถ้าคัดลอกมา เซิร์ฟเวอร์จะสตาร์ทไม่ขึ้น

## ขั้นที่ 3 — วางข้อมูลลงเครื่องใหม่

| จาก | ไป |
|---|---|
| `backups\<ล่าสุด>\identifier.sqlite` | `<เครื่องใหม่>\server\identifier.sqlite` |
| `backups\<ล่าสุด>\uploads\` | `<เครื่องใหม่>\server\uploads\` |
| `env-backup.txt` | `<เครื่องใหม่>\server\.env` |

> 💡 รูปภาพในฐานข้อมูลเก็บเป็น path แบบสัมพัทธ์ (`/uploads/ชื่อไฟล์`)
> **จึงไม่ต้องแก้ข้อมูลอะไรเลยหลังย้าย** แค่คัดลอกโฟลเดอร์ให้ครบ

## ขั้นที่ 4 — แก้ `server/.env` ให้ตรงโดเมนใหม่

### ต้องเปลี่ยน

| ตัวแปร | เปลี่ยนเป็น | ถ้าลืมจะเป็นยังไง |
|---|---|---|
| `FRONTEND_URL` | `https://<โฮสต์ใหม่>` | เว็บใช้ได้ปกติ **แต่ลิงก์รีเซ็ตรหัสผ่านพาไปโดเมนเก่า** — สังเกตยากมาก |
| `VAPID_SUBJECT` | `https://<โฮสต์ใหม่>` | ข้อมูลติดต่อของระบบแจ้งเตือนไม่ตรง |
| `BOOTSTRAP_ADMIN_EMAIL` | อีเมลองค์กร | (ถ้าเดิมเป็นอีเมลส่วนตัว ควรเปลี่ยนตอนส่งมอบ) |

> `FRONTEND_URL` ใส่หลายค่าได้โดยคั่นด้วยจุลภาค แต่ **ต้องใส่โดเมนจริงไว้ตัวแรก**
> เพราะลิงก์ในอีเมลใช้ค่าตัวแรกเป็นหลัก

### ต้องคัดลอกมาเหมือนเดิมทุกตัวอักษร

| ตัวแปร | ถ้าเปลี่ยนจะเกิดอะไร |
|---|---|
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | **ห้ามสร้างใหม่** ถ้าสร้างใหม่ ระบบแจ้งเตือนของผู้ใช้เดิมจะพังถาวร |
| `EMAIL_USER` / `EMAIL_PASS` | ส่งอีเมลรีเซ็ตรหัสผ่านไม่ได้ |
| `JWT_SECRET` | คนที่ล็อกอินค้างไว้จะหลุดทั้งหมด ต้องล็อกอินใหม่ *(ถ้าตั้งใจให้หลุดหมดก็เปลี่ยนได้ ถือเป็นการล้าง session ตอนส่งมอบ)* |

> 📌 **เรื่องแจ้งเตือน (push)**: ถึงจะเก็บคู่กุญแจเดิมไว้ แต่การแจ้งเตือนผูกกับโดเมน
> **ผู้ใช้ทุกคนต้องกดเปิดแจ้งเตือนใหม่บนโดเมนใหม่อยู่ดี** — ควรแจ้งทีมล่วงหน้า

## ขั้นที่ 5 — build และทดสอบในเครื่องก่อนเปิด Tunnel

```powershell
cd <เครื่องใหม่>
npm run build
cd server
npm start
```

ต้องเห็นครบ 3 บรรทัด:
```
📂 Using database: <เครื่องใหม่>\server\identifier.sqlite
🌐 Serving built frontend from dist/
🚀 Server running on port 5000
```

เปิด `http://localhost:5000` บนเครื่องใหม่ → ล็อกอิน → **เช็คว่าข้อมูลมาครบ**
(สินค้า, รูปภาพ, ผังคลัง, ประวัติใบเบิก) แล้วค่อยไปขั้นต่อไป

กด `Ctrl+C` ปิด

## ขั้นที่ 6 — ตั้ง Cloudflare Tunnel + Access + pm2

ทำตาม [CLOUDFLARE_SETUP.md](CLOUDFLARE_SETUP.md) **ขั้นที่ 4 ถึง 9** โดยใช้ `<โฮสต์ใหม่>`

จุดที่ต่างจากการติดตั้งใหม่:
- สร้าง **tunnel ใหม่** สำหรับเครื่องนี้ (tunnel เดิมผูกกับเครื่องเดิม ย้ายไม่ได้)
- ตั้ง Public Hostname เป็น `<โฮสต์ใหม่>` Type **HTTP** → `localhost:5000`
- **ยังไม่ต้องปิดเครื่องเดิม** จนกว่าจะตรวจรับเสร็จ

---

## ขั้นที่ 7 — ตรวจรับ

ใช้ตารางตรวจรับใน [CLOUDFLARE_SETUP.md](CLOUDFLARE_SETUP.md) (10 ข้อ) ให้ครบ
โดยเน้นเป็นพิเศษ 3 ข้อนี้ เพราะเป็นจุดที่การย้ายมักพลาด:

| ข้อ | ทดสอบ | ถ้าไม่ผ่านแปลว่า |
|---|---|---|
| 2 | รูปสินค้าขึ้นครบ | คัดลอก `uploads/` ไม่ครบ |
| 6 | ลิงก์รีเซ็ตรหัสผ่านเป็นโดเมนใหม่ | `FRONTEND_URL` ยังเป็นค่าเก่า |
| 3 | ผังคลังเห็นห้อง/ชั้นวาง/ตำแหน่งสินค้า | ฐานข้อมูลย้ายไม่ครบ (อาจคัดลอกไฟล์ตรงๆ แทนที่จะใช้ backup) |

## ขั้นที่ 8 — ตัดระบบเก่า

**หลังตรวจรับผ่านครบแล้วเท่านั้น:**

1. แจ้งผู้ใช้ทุกคนว่าเปลี่ยนไปใช้ `https://<โฮสต์ใหม่>` แล้ว
2. แจ้งให้ **กดเปิดแจ้งเตือนใหม่** และ **ติดตั้ง PWA ใหม่** บนโดเมนใหม่
3. บนเครื่องเดิม: `pm2 stop wms` แล้ว `pm2 delete wms`
4. ปิด/ลบ tunnel เดิมใน Cloudflare dashboard
5. **เก็บเครื่องเดิมไว้อย่างน้อย 2 สัปดาห์** (อย่าเพิ่งลบข้อมูล) เผื่อพบปัญหาแล้วต้องย้อนกลับ

> 💡 **ช่วงเปลี่ยนผ่าน**: ถ้าอยากให้ทั้งโดเมนเก่าและใหม่ใช้งานได้พร้อมกันชั่วคราว
> ให้ใส่ทั้งสองค่าใน `FRONTEND_URL` คั่นด้วยจุลภาค (โดเมนใหม่ไว้ตัวแรก)
> แต่ต้องระวังว่า **ฐานข้อมูลจะแยกกันคนละก้อน** ข้อมูลที่ป้อนในเครื่องเก่าจะไม่มาที่เครื่องใหม่
> — วิธีที่ปลอดภัยกว่าคือตัดไปใช้เครื่องใหม่ทีเดียวเลย
